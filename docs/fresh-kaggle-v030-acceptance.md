# Fresh Kaggle 0.3.0 acceptance from corrected split-v2 Inputs

The final SDK acceptance uses the already-uploaded corrected runtime-core-v2, runtime-large-v2, torch-cu129-v2, and wheelhouse-audit-v2 Datasets under the configured Kaggle Input root. The lean P33 lock selects 168 dependency wheels from those corrected Inputs. The small final SDK Dataset contains only the SDK and acceptance assets. A saved P31 Notebook Output or the separate native-wheel-only Dataset supplies the immutable native vLLM wheel. Attach the Kaggle-provided Gemma 4 QAT Input Model. **No runtime-v3 upload is needed.** Start a new CPython 3.12, four-L4 session with Internet off.

The P33 `selected_wheels.txt` and install log show that the 168 dependency wheels omit `packaging` and `jinja2`. Since the qualified run succeeded, these packages resolved outside the selected wheel set; the saved P33 evidence does not record their exact import origins. The final SDK runner installs the SDK with `--no-deps`, so it now checks both packages before runtime staging and saves their versions and import locations in `evidence/02_base_dependencies.json`. This is an explicit target-image dependency. Do not add unvalidated wheels to the P33 lock merely because they appear in the broader runtime-v3 closure.

Use the exact launch command in [README-RUN-ME-FIRST](../release/README-v0.3.0-production-acceptance.md), or run the output-free [notebook](../kaggle-notebooks/kaggle_vllm_0_3_0_l4x4_final_sdk_acceptance.ipynb). The default mode is `SPLIT_V2_KAGGLE_INPUTS`. The runner refuses duplicate corrected sources and validates every selected wheel against both its pinned runtime manifest and the corrected wheelhouse-audit manifest before pip staging. The SDK-owned target uses `--no-index --no-deps` and no source compilation.

Use `--native-wheel <exact-mounted-wheel>` or `--p31-archive <exact-mounted-final-v2-tar>` to override native discovery. Use `--notebook-root <mounted-output-root>` when the saved Notebook Output is not under `/kaggle/input/notebooks/`. Use `--input-root <parent-of-corrected-datasets>` if the Dataset owner mount differs. Use `--gemma-model <single-valid-version-directory>` when multiple Gemma versions are mounted.

For a future permitted release environment with the archive already attached, use `--runtime-mode RUNTIME_V3_ARCHIVE --runtime-archive <exact-mounted-runtime-v3-tar>`. This optional mode is **not** the current required path.

Steps 0–20 cover input inventory, hardware, SDK hash, corrected components, P31 native source, full wheel/native integrity, SDK install, isolated bootstrap and activation, Torch/cu129, doctor, vLLM/core/FA2 import, libcuda link, NCCL TP4, Gemma discovery/semantic chat, worker cleanup, matrix, and evidence ZIP. Long-running subprocesses stream logs, have deadlines, and are cleaned as process groups.

The competition notebook runs **only** the supported Gemma 4 QAT model.
